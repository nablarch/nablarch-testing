# T5 完了条件チェック

タスク: 変換ツールに検証モード（リンタ）を追加
参照文書: 設計書 §10（本タスクで追記）
変更対象: 新規 `YamlTestDataValidator`・`ValidationError`（`yaml` パッケージ）、`TestDataConverter` への組込み、対応するテスト

## 実施手順（TDD）

1. RED: 不正 YAML でエラーが報告されることを検証するテストを追加し、空実装で失敗を確認した。
   - 列数不一致（`fields` 件数 ≠ いずれかの `rows` 配列長）
   - 構造境界違反（既知ディレクティブ名が `fw_header:` にある）
   - スキーマ非適合
2. GREEN: 上記3点の検証を実装した。列数一致は各 `record_fragment` で `fields` 件数と各 `rows` 配列長を照合。スキーマ適合は `ntf-testdata-yaml-schema.json` で検証。
3. 失敗時に「ファイル・位置・内容」を構造エラー一覧として出力する。「検証のみ」（`--validate`）と「変換時に検証し失敗で中断」（`--validate-on-convert`）の2モードを提供した。
