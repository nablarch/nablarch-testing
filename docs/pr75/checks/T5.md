# T5：検証モード（リンタ）の追加

## 背景と決定

不正な YAML を変換前に検出するため、変換ツールに検証モード（リンタ）を追加した。

- 参照文書: 設計書 §10（本タスクで追記）
- 変更対象: 新規 `YamlTestDataValidator`・`ValidationError`（`yaml` パッケージ）、`TestDataConverter` への組込み、対応するテスト

検出する 3 つの不正と、実装上の照合方法は次のとおり（TDD で RED→GREEN を確認済み）。

| 検出対象 | ルールコード | 照合方法 |
|---|---|---|
| 列数不一致（`fields` 件数 ≠ いずれかの `rows` 配列長）| [V-COL] | 各 `record_fragment` で `fields` 件数と各 `rows` 配列長を照合 |
| 構造境界違反（既知ディレクティブ名が `fw_header:` にある）| [V-DIR] | — |
| スキーマ非適合 | [V-SCH] | `ntf-testdata-yaml-schema.json` で検証 |

失敗時は「ファイル・位置・内容」を構造エラー一覧として出力する。実行モードは 2 種類。

- `--validate`：検証のみ
- `--validate-on-convert`：変換時に検証し、失敗で中断

# T5-ext：バリデータへのルール追加（シフトレフト拡張）

## 背景と決定

不正をより早期に検出するため、バリデータにルールを追加した。

- 参照文書: 設計書 §10.3
- 変更対象: `YamlTestDataValidator`・`YamlTestDataValidatorTest`

初版（2026-06-02）では V-FNAME / V-DKEY / V-MSGROW の 3 ルールを追加した。TDD で V-FNAME（フィールド名重複）・V-DKEY（不正ディレクティブキー）の失敗テストを RED で確認し、`validateFieldNames`・`validateDirectiveKeys` の 2 メソッドで GREEN にした。

最終的に採用したルールは V-FNAME / V-DKEY の 2 つ。

| ルール | 検出対象 |
|---|---|
| V-FNAME | 同一 `record_fragment` 内のフィールド名重複（異なる fragment 間の同名は検出しない）|
| V-DKEY | `directives` の未知キー |

## 差し戻し：V-MSGROW の削除（2026-06-03）

ユーザーレビューにより V-MSGROW を削除した。**実データで header/body の行数が一致しない異常系テストが多数存在し、制約として成立しない**ため。

差し戻し対応として `validateMsgRowCounts`・`countTotalRows`・関連定数（KEY_EXPECTED_REQUEST_* 等）・V-MSGROW テスト 7 件を削除した。これにより public API（`validate` シグネチャ）は不変を保ち、不要になった定数・メソッドも併せて除去して整合性を維持した。
