## 実施手順（TDD）

1. RED: FW制御ヘッダ＋電文ボディ＋複数データ行を持つ実 messaging Excel（`MessageParserTest.xls`、`MessagingRequestTestSupportTest.xls` の testSuccess 等）を変換し、出力 YAML が下記を満たすことを検証するテストを追加し、現状の失敗（混入・1列ずれ・データ消失）を確認する。
   - `MESSAGE`: `text-encoding` が `directives:`、`requestId`/`userId` が `fw_header:`、電文本文が `records` の `fields`/`rows`
   - `EXPECTED_REQUEST_*`/`RESPONSE_*`: `text-encoding` が `directives:`、`requestId` 等を含む全フィールドが `records` の `fields`/`rows`（`fw_header` は出力しない）
2. GREEN: `parseMessageBlock` の状態機械を、識別行→（ディレクティブ または FW制御ヘッダ の「名前｜値」群）→ 先頭セル `no` のフィールド名称行 → 型行 → 長さ行 → データ行 の順で解釈するよう修正する。`名前｜値` を既知ディレクティブ名と FW制御ヘッダ名（`reader.fwHeaderfields`）に振り分ける。
3. `MessageDataBlock` を `directives`（Map）・`fwHeader`（Map）・`records` に分けて保持する形へ整理する。
4. `YamlFormatWriter` を、`MESSAGE` は `directives:`/`fw_header:`/`records:`、`expected_request_*`/`response_*` は `directives:`/`records:`（`fw_header` なし）で出力するよう修正する。
