# P1-2 Completion Check — #2 本体 YAML 読み込みの 2 層分離（判断 B / option C）

対象タスク: Phase 1 / #2（本体 YAML 読み込みの 2 層分離）
設計書: `docs/pr75/docs/testdata-converter-design.md`（判断 B）／決定 D-F（option C）

## やったこと（要約）

YAML 読み込みを **構造マッピング層**（値未加工で生の構造レコード `Raw*` を返す）と
**値加工＋組み立て層**（`Raw*` → 本体器）に明示分離した（D-F option C）。

1. **生の構造レコード `Raw*` 6 クラス**（`reader.yaml.model`）を新設。すべて `final`・不変・値未加工。
   - `RawTableData` / `RawListMap` / `RawDataFile` / `RawRecordLayout` / `RawFieldDef` / `RawMessage`
   - マーカーカラム保持・YAML 記述順保持・長さ省略 `null`・FW_HEADER 保持・**大文字化なし**。
   - `RawMessage.fwHeader` は生の `Object`（マップとは限らない）として保持＝検証を後段へ遅延。
2. **構造マッピング層**（変換ツールと共有する公開 API）を新設。
   - `YamlTableStructureMapper`（`mapTables`/`mapListMaps`）・`YamlFileStructureMapper`（`mapFiles`＋共通 `mapRecords`/`mapDirectives`）・`YamlMessageStructureMapper`（`mapMessages`、本文写しは File 側を再利用＝重複ゼロ）。
   - interpret・補完・大文字化・マーカー除外・グループ絞り込みを **一切持たない**（純粋）。
3. **値加工＋組み立て層** `YamlValueProcessor` を新設（本体テスト専用）。
   - `Raw*` を受け、interpret／`${binaryFile:}` basePath 解決／メッセージ長 `-` 注入／`fillDefaultValues`／マーカー除外／グループ絞り込み／list_maps の `TreeMap` ソートを施し本体器を組み立てる。
4. **`YamlTestDataParser`** を「structureMapper → valueProcessor」の明示 2 呼び出しへ再配線。
   - 旧実装の「空 interpreters を渡すと加工が外れる」**暗黙切替を廃止**。`setDbInfo/setInterpreters/setDefaultValues` で valueProcessor を再構築。
5. 旧 builder 3 本（`YamlFileBuilder`/`YamlMessageBuilder`/`YamlTableDataBuilder`）を **削除**。
6. builder テスト 73 件を valueProcessor＋mapper 経由へ移送＋構造層テスト（`YamlTableStructureMapperTest` 5 件）新設。

## 実装で確定した設計判断（#7 へ波及・本文 D-F に昇格済み）

- **空マッピング `{}` 行**: 構造層が **空リスト `[]`** として保持（行の有無を後段が判別）。テーブルは値加工層でスキップ、list_maps は空行として残す（本体差異を再現）。
- **`fw_header` 検証の遅延**: 「マップであること」の検証は値加工層が **実際に読み出すメッセージに対してのみ** 実行。同一ファイル内の誤記エントリが他エントリ読み出しを巻き添えにしない旧挙動を維持。
- **`toTableDataList`/`toDataFileList` の `sectionKey` 引数**: 例外メッセージ用（テストがセクション名を要求）。
- **list_maps 出力**: 値加工層は `TreeMap` 維持（本体不変）、`RawListMap` は YAML 順保持（変換ツール用）。
