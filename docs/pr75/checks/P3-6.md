# P3-6 (#6 XlsFormatReader 再構築) Completion Check

## 設計判断（着手時・アーキテクトレビュー反映）

アーキテクトサブエージェントの検証（verdict）＋実コード確認で以下を確定。

### (A) read() 粒度 — 単一セクション
`XlsFormatReader.read(basePath, resource)` は 1 リソース（"ブック名/シート名"）を読み 1 `TestDataSection` を持つ `TestDataContainer` を返す。シート列挙（POI 必須）・ディレクトリ走査は #10（`ConverterPathResolver`）へ委譲。`PoiXlsReader.getSheetNames` は静的・`TestDataReader` 外なので #6 で触らない＝POI 直叩き構造判定の混入を防ぐ。

### (B) マーカー/グループ列挙 — アダプタに `readHeaders` を新設
本体パッケージ相乗りのアダプタ（`TestDataParserAdapter`）に `readHeaders(path, resource) → List<BlockHeader>` を追加。本体 `TestDataParsingTemplate#getDataType`/`getTypeValue`（protected final）を**再利用**してマーカー分類するため、本体の行分類ロジックをフォークしない（6.3 不整合の根治＝二重実装解消の趣旨に合致）。`XlsFormatReader` は分類済み `DataType` enum で分岐するのみ（＝オーケストレーション。構造解析を持たない）。
- `BlockHeader{DataType type, String groupId, String identifier}`。
- 矛盾する `id` セマンティクスをアダプタ API 実証から確定：
  - TABLE/FILE 系（`GroupDataParsingTemplate`）：`id = groupId`（`name + groupId + '='` で照合）。1 回呼ぶと当該グループの全器が返るので **(type, groupId) で重複排除**して 1 回だけ読む。
  - LIST_MAP/MESSAGE（`SingleDataParsingTemplate`）：`id = identifier`（`=` 以降の値で照合・group は無視）。ヘッダごとに 1 回読む。

### (C) MESSAGE 本文 — アダプタが本文 FixedLengthFile を公開
`readMessage` の戻り値を `MessagePool` から `MessageData{Map<String,String> fwHeader, FixedLengthFile body}` へ変更。本文は `MessageParser#getDelegate().getResult()`（本体パッケージからのみ可視）で取得。`MessagePool#getSource()` は protected で変換ツールパッケージから不可視のため、本文露出はアダプタの責務（設計書 §共通・行 225 と一致）。#5 の readMessage テスト 2 件を `MessageData` 利用へ更新。

### スコープ確定（#6 が網羅する種別）
- **網羅**: TABLE（SETUP/EXPECTED/EXPECTED_COMPLETE）・LIST_MAP・FILE（FIXED/VARIABLE × SETUP/EXPECTED）・MESSAGE（FW ヘッダ＋本文）。
- **#6 で先送り**: 要求/応答電文 4 種（`EXPECTED_REQUEST_HEADER/BODY_MESSAGES`・`RESPONSE_HEADER/BODY_MESSAGES`）。理由：これらは `SendSyncMessageParser`/`GroupMessageParser`（caseNo グループ・`RequestTestingMessagePool`）という別パーサ経由で、本文を `RequestTestingMessagePool`（別パッケージ・protected `getSource()`）から取り出すには**追加の本体露出**が要る。アーキテクトが提案した「readFiles 経由」は実コード照合で誤り（別パーサ・本文取り出し口が異なる）と判明したため、conflate せず別途 TDD で扱う。`MessageDataBlock` は 5 種別対応済ゆえ後追い追加は非破壊。**6.3 コーパスが当該 4 種を使うか #14 前に確認**し、使うなら #14 前に追加実装する。

> 注: この先送りにより #6 の完了条件「全種別を無損失で中間モデル化」は厳密には MESSAGE 系の一部未達。正確性（誤実装回避）を優先した意図的スコープ。下記セルフチェックで該当条件を「部分OK（先送り明記）」として根拠記録する。
