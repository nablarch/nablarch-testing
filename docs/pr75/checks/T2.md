# T2 完了条件チェック

タスク: fw_header マップ対応（ランタイム、messages 限定）
参照文書: 設計書 §12、解説書 §7.2、スキーマ `$defs/message_data/fw_header`・`$defs/fw_header`、仕様リスト MS-01/MS-04
変更対象: `src/main/java/nablarch/test/core/reader/yaml/YamlMessageBuilder.java`、`YamlFileBuilder.java`、`src/test/.../YamlMessageBuilderTest.java`

## 実施手順（TDD）

1. RED: `messages` エントリ直下の `fw_header:` マップ（既定キー＋プロジェクト独自キー両方）を持つ YAML を読み、`MessagePool#getFwHeader()` が記述した全キー:値を返すことを検証するテストを追加し、失敗を確認する。`reader.fwHeaderfields` に無いキーも捨てられず保持されることを確認するケースを含める。
2. GREEN: `YamlMessageBuilder.extractFwHeader` を、`records` 内 `FW_HEADER` レコード探索方式から、エントリ直下 `fw_header:` マップ読込方式に書き換える。`fwHeaderFields.contains(...)` フィルタを廃止し全エントリを `fwHeader` Map に入れる。この読込は `getMessage`（messages）経路のみ。
3. `getMessageWithoutCache`（`expected_request_*`/`response_*`）経路は `extractFwHeader` を呼ばず空 Map を渡すよう是正する。
4. `YamlFileBuilder` の `FW_HEADER` レコードスキップ処理を見直し、`records` 側に `FW_HEADER` レコードが現れない前提に整理する。
5. スキーマ `03` の `$defs/fw_header`・`message_data.fw_header` を適用する（`group_message_data` には付けない）。
6. `record_type` が常に `"default"` 化されること、`response_*` の `errorMode` 行が `fw_header` 分離と独立に共存することを検証するテストを追加する。
